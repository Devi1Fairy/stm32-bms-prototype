# 首次采样：ADC1单通道与两个已知输入

日期：2026-10-17。前置HSE/PLL版本为01bb62d，用户反馈成功。当前ADC未配置；本步为待用户实施的教程，助手未改源码或工程。

## 本步唯一目标

先验证ADC1的PC0通道：启动时校准并读取一次，将结果存入adc_raw，在Keil Watch查看。分两次接开发板GND与3V3，验证低端和高端读数。通过后下一步再接电位器，做周期读取、换算和串口显示。

本步保留已有LED及固定UART文本，只增加一次启动采样。它不代表BMS电池电压采集、滤波、故障检查或DMA已实现。

## 1. 引脚、时钟与输入依据

- 本地F103xCDE英文数据手册Rev7 PDF第30页、中文数据手册第20页，PC0标为ADC123_IN10：可以作为ADC1/2/3的通道10。本步只用ADC1。
- 双USB核心板配套原理图第4页PC0只引用排针页，第5页J4区域引出PC0。已渲染并目视核对；按板上PC0丝印或板卡IO图找对应排针，不凭照片猜方向或从MCU封装脚号直接数排针。
- PC0未见板载外围负载，可用于该信号实验。其他ADC引脚可能复用按键、SPI等，后续按原理图分配。
- 当前HSE/PLL为72 MHz，PCLK2为72 MHz，.ioc仍记录ADCFreqValue=36000000。此前ADC未启用，本步启用时必须把ADC分频设为/6，得到12 MHz，满足14 MHz上限。
- 配套原理图模拟参考与板上3.3 V供电有关。本步输入只来自同一开发板GND或3V3，限定在ADC参考范围；5V、真实电芯或串联电池抽头不接该输入。
- 电位器RV0932-B103的引脚/安装形式及万用表持有情况仍未确认。本步使用已知电平推进，无需猜电位器引脚。

ADC把参考范围内的模拟电压转换成整数。F103为12位，右对齐后范围0～4095；本步先读原始数字量，实际毫伏换算与基准电压校准在后续处理。

## 2. CubeMX配置ADC1

退出Keil调试并保存VS Code文件，打开原有bms_bringup.ioc。

1. Analog → ADC1，启用IN10，确认PC0分配为ADC1_IN10。
2. 只配置一个规则转换通道，序列Rank 1为Channel 10。
3. 按表核对Parameter Settings，不添加ADC中断或DMA。

| 项目 | 设置 | 原因 |
| --- | --- | --- |
| ADC模式，若显示 | Independent | 独立使用ADC1 |
| Scan Conversion Mode | Disabled | 只采一个通道 |
| Continuous Conversion Mode | Disabled | 每次由软件启动一轮 |
| Discontinuous Conversion Mode | Disabled | 当前只有一个转换序列项 |
| External Trigger Conversion | Software Start | 使用HAL_ADC_Start触发 |
| Data Alignment | Right | 结果可直接按0～4095读取 |
| Number of Conversion | 1 | 序列仅一个通道 |
| Rank 1 | Channel 10 | 与PC0对应 |
| Sampling Time | 239.5 Cycles | 初期用较长采样窗口，给内部采样电容充电时间 |
| 分辨率 | 固定12位 | F103不需要寻找可切换分辨率选项 |

通道编号与序列位置不同：Channel 10是PC0对应的硬件输入，Rank 1表示这轮转换中的第一个位置。

到Clock Configuration将ADC Prescaler设为/6，确认ADC为12 MHz；保留SYSCLK/HCLK 72 MHz、PCLK1 36 MHz、PCLK2 72 MHz。12 MHz是ADC工作时钟，不是每秒读取1200万次；当前239.5个采样周期加12.5个转换周期，单次理论约21 µs，程序另有启动等开销。

保存并生成，保持CubeF1 1.8.7、MDK-ARM V5、用户代码保留及外设分文件生成。

预计新增Core/Inc/adc.h和Core/Src/adc.c。确认：

- main.c自动包含adc.h，并在USER CODE BEGIN 2之前调用MX_ADC1_Init。
- adc.c中句柄为hadc1，Instance为ADC1，通道ADC_CHANNEL_10、Rank 1、ADC_SAMPLETIME_239CYCLES_5。
- ADC初始化包含PC0模拟输入及GPIOC、ADC1时钟。模拟输入无需上下拉；CubeMX生成的模拟GPIO配置按HAL实现保留。

- stm32f1xx_hal_conf.h自动启用HAL_ADC_MODULE_ENABLED；Keil工程包含adc.c、stm32f1xx_hal_adc.c和stm32f1xx_hal_adc_ex.c。
- 原有GPIO、USART1、用户BMS文件引用仍保留；主机tests不能加入Keil。

## 4. 用户编写代码

### 增加调试观察变量

在main.c现有USER CODE BEGIN PV区追加以下内容，保留uart_message和两个计时变量：

```c
/* 初值超出12位ADC范围，方便确认采样代码确实执行过。 */
static volatile uint32_t adc_raw = 0xFFFFFFFFu;
```

uint32_t与HAL_ADC_GetValue的返回类型一致。volatile让程序保留对该变量的实际访问，便于调试观察；它不提供任务互斥或线程安全。0xFFFFFFFF为本步调试用“尚未采样”标记，不是有效测量值。后续采用正式BmsMeasurement有效标记与时间戳。

### 初始化中完成一次采样

把main.c的USER CODE BEGIN 2区域替换为下列内容，确保所有MX初始化调用在它之前：

```c
/* USER CODE BEGIN 2 */

    /* 上电后做一次ADC内部校准，减小内部偏差。 */
    if (HAL_ADCEx_Calibration_Start(&hadc1) != HAL_OK)
    {
        Error_Handler();
    }

    /* 软件启动一次转换。 */
    if (HAL_ADC_Start(&hadc1) != HAL_OK)
    {
        Error_Handler();
    }

    /* 等待本次转换完成；10u是超时上限，单位为毫秒。 */
    if (HAL_ADC_PollForConversion(&hadc1, 10u) != HAL_OK)
    {
        Error_Handler();
    }

    /* 读取原始数字量。12位、右对齐时，正常范围为0～4095。 */
    adc_raw = HAL_ADC_GetValue(&hadc1);

    /* 本次读取结束，关闭ADC，后续需要采样时再启动。 */
    if (HAL_ADC_Stop(&hadc1) != HAL_OK)
    {
        Error_Handler();
    }

    /* 保留原有LED和串口计时，从初始化完成后开始计时。 */
    led_last_ms = HAL_GetTick();
    uart_last_ms = led_last_ms;

/* USER CODE END 2 */
```

这些代码只在每次启动/复位时执行一次。改变接线后需要复位或重新上电，adc_raw才会更新；F5继续while并不会再采一次。

校准、启动、等待、读取、停止各自负责不同阶段。PollForConversion采用阻塞等待，10 ms为超时上限，正常转换约几十微秒量级；本步在启动阶段验证，不将其宣称为实时采样或最终保护策略。Error_Handler沿用当前外设验证方式，后续采样失败改为报告无效或超时故障。

保留原来的while：LED500 ms翻转、UART200 ms发送固定文本。串口此时仍不输出adc_raw。

## 5. 分两次接线与验收

### 第一次：低端输入

1. 退出调试，断开开发板与ST-LINK的USB供电后接线。
2. 一根杜邦线连接PC0与开发板GND。
3. 恢复板卡USB与调试器供电，RST仍留空。
4. Keil F7构建、F8下载。
5. 在USER CODE BEGIN 2末尾的led_last_ms = HAL_GetTick()处F9设断点。到达它时，校准、转换、读取及停止已经执行。
6. 进入调试并F5运行到该断点，在Watch添加adc_raw，期望在0附近。若显示0xFFFFFFFF（十进制4294967295），说明尚未写入有效读数，不能把初始化值当作成功采样。
7. F5继续，原LED及串口应继续运行。

### 第二次：高端输入

1. 退出调试并断开板卡与ST-LINK的USB供电。
2. 移除PC0到GND的连接，改为PC0到同一板卡3V3。两次接线分别进行，PC0每次只接一个测试点。
3. 重新上电，不需要修改代码或重新生成。进入调试，运行到相同断点。
4. adc_raw应在4095附近；F5继续后原LED及UART仍工作。

两点测试证明通道选择与基本转换链路可用，没有中间电压测试或精确标定记录时，不宣称ADC全量程精度、线性或电池采样已验证。零附近/满量程附近是预期趋势，不凭教学示例承诺固定误差限。

PC0悬空时读数可能漂移，悬空不是本步验收条件。代码只启动读取一次，后续接电位器时再改为周期采样。

## 6. 反馈与问题入口

反馈三项：编译结果、PC0接GND的adc_raw、PC0接3V3的adc_raw。保留实际数值，不把预期值代写成测量值。

| 现象 | 首先核对 |
| --- | --- |
| adc_raw仍为0xFFFFFFFF | 是否运行到读取之后、新代码是否保存并下载 |
| 两种接线均接近0 | PC0排针位置、3V3测试点和新固件 |
| 两种接线均接近4095 | 接线与通道对应、PC0是否实际接到GND |
| 值偏离两个预期端点很多 | 通道、ADC时钟、输入连接与供电参考；保留数值后再排查 |
| 停在Error_Handler | 从调用位置分辨校准、启动、等待、停止哪个步骤失败 |
| 校准函数链接失败 | Keil是否加入HAL ADC扩展驱动、配置是否完整生成 |

这些为排查方向，尚未发生时不写成已遇到并解决的问题。
