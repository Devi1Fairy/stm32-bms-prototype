# 无板练习 01：定义采样数据类型

日期：2026-10-15。状态已更新：用户完成头文件和 main.c 包含行，Keil 编译通过，并以提交 7863ef6 保存；开发板尚无到货和运行验证记录。下文保留最初练习步骤供回看，实际 bms_types.h 已有通俗中文注释，无需重新覆盖。

## 本次唯一目标

为电压、电流、温度建立共用的数据格式，将头文件包含到当前 Keil 工程并编译通过。暂不实现 ADC、CAN、保护判断和状态机；本轮没有硬件接线。

采样任务以后提供这些数据，保护模块读取它们，CAN 模块按协议编码它们。先统一格式，可以减少后续各模块对单位、有效性和更新时间的不同理解。

## 第一步：新建 bms_types.h

在当前工程 Core/Inc 下新建 bms_types.h，即：

```text
D:\嵌入式学习\电池管理系统\MCU\projects\bms_bringup\Core\Inc\bms_types.h
```

写入以下内容：

```c
#ifndef BMS_TYPES_H
#define BMS_TYPES_H

#include <stdint.h>

#define BMS_CELL_COUNT 3u

typedef enum
{
    BMS_SOURCE_NONE = 0,
    BMS_SOURCE_SIMULATED,
    BMS_SOURCE_ADC,
    BMS_SOURCE_AFE
} BmsSampleSource;

typedef struct
{
    int32_t value;
    uint32_t timestamp_ms;
    uint8_t valid;
    BmsSampleSource source;
} BmsMeasurement;

typedef struct
{
    BmsMeasurement cell_mv[BMS_CELL_COUNT];
    BmsMeasurement current_ma;
    BmsMeasurement temperature_dC;
} BmsSample;

#endif
```

### 为什么这样写

| 内容 | 含义与原因 |
| --- | --- |
| #ifndef / #define / #endif | 头文件保护，防止同一编译单元重复包含后重复定义类型 |
| stdint.h | 提供 int32_t、uint32_t、uint8_t 等明确位宽的整数类型 |
| BMS_CELL_COUNT 3u | 当前默认 3 串，用一个宏统一数组长度；u 表示无符号整数字面量 |
| typedef enum | 定义一组有名称的来源值，并将类型命名为 BmsSampleSource |
| typedef struct | 将相关字段组织成一份数据，并提供 BmsMeasurement 或 BmsSample 类型名 |
| 嵌套结构体 | 每一路测量都带自己的数值、时间、有效性和来源，多个测量组成一个采样快照 |

来源字段的含义：NONE 表示未取得数据；SIMULATED 表示软件构造的数据；ADC 表示经 MCU ADC 获取；AFE 表示经电池采样前端获取。声明这些名称不等于已经实现对应驱动。ADC 只说明采集路径，电位器模拟电池电压的实验仍必须在文档中标为模拟输入。

### 每个测量字段的作用

- value：当前测量值。第一版统一使用 int32_t，方便表示有符号电流、负温度，并减少初次练习中的类型差异；有效电压仍要求非负，具体范围检查后续加入。
- timestamp_ms：取得新采样时的毫秒时间，后续可以使用 HAL_GetTick。它表示 MCU 启动后的时间计数，并非年月日。CAN 重复上报旧值时不能刷新该字段。
- valid：0 表示不可用于正常测量判断，1 表示已通过当前采集及有效性检查。有效性和新鲜度分别判断，valid=1 仍可能因时间过旧而超时。
- source：保留数据来源，便于演示时区分软件构造数据、ADC 输入和 AFE 数据。

每个单体电压、总电流、温度均拥有这些字段，以适应不同刷新节奏。不能因温度更新了，就把旧电压的时间也更新。

### 数值单位约定

| 字段 | 单位与示例 |
| --- | --- |
| cell_mv[0].value | 第 1 节单体电压，单位 mV；3700 表示 3.700 V |
| current_ma.value | 电流，单位 mA；本练习约定正数为放电、负数为充电，接真实采样后需校验方向 |
| temperature_dC.value | 温度，单位 0.1℃；250 表示 25.0℃，-50 表示 -5.0℃ |

统一整数单位便于后续阈值比较和 CAN 编码。数组下标从 0 开始，三节对应 cell_mv[0]、cell_mv[1]、cell_mv[2]。

这里只定义类型，没有创建 BmsSample 变量，也没有初始化或获取任何测量值。以后创建 BmsSample sample = {0} 时，valid 和 source 的零值将表示尚未取得有效数据，不能把 value=0 当作一次真实零电压采样。

## 第二步：让 main.c 包含新头文件

打开 Core/Src/main.c，在已有 USER CODE Includes 区域加入：

```c
/* USER CODE BEGIN Includes */
#include "bms_types.h"
/* USER CODE END Includes */
```

目的：让 C 编译器在编译 main.c 时读取新类型定义，并检查头文件内容。Keil 已有 Core/Inc 的头文件搜索路径，因此此处直接使用文件名即可。头文件经 #include 参与编译，不需要像新增 .c 那样加入编译源文件列表；为了便于编辑，可以在 Keil 工程树中添加其显示项。

放入 USER CODE 区域，是为了利用当前 Keep User Code 设置，在以后 CubeMX 重新生成时保留该手写包含行。
