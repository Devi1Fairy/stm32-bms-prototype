## 需求、架构与预算

### 第一版演示目标

在电脑发送 START 后，系统允许小功率负载工作，并通过 CAN 上报测量值、状态与故障。注入某一路电压、电流、温度异常，或停止有效采样后，系统关闭负载并进入故障锁定。异常消失后仍不自动运行；满足恢复条件并收到 CLEAR 才回到待机，再次收到 START 才允许运行。

先按 3 串数据模型实现，数组容量可保留到 5 串；第一版不以验证全部串数配置为前提。硬件负载演示暂定使用 5～12 V 的限流直流电源、约 0.05～0.3 A 电阻性负载，第一次通电从更低限流和小功率开始。具体电流、保险丝和负载功率在模块确认后计算。

这里的 3 串模拟数据和负载电源是两个概念：五个 ADC 模拟输入可以分别代表三个单体电压、一路电流和一路温度，并不代表已经连接真实电池组。

#### 状态与控制规则

- 上电/复位先关闭输出，再自检。自检通过且取得完整有效数据后进入待机，失败进入故障锁定。
- 待机收到 START，且所有使能条件成立，才进入运行。
- 运行收到 STOP，关闭负载并进入待机。若同一轮还有保护故障，故障锁定优先。
- 任一活动保护故障关闭负载并进入故障锁定；锁定状态下 START 无效，STOP 也不能解除锁定。
- 暂定恢复区间内持续稳定 2 s，且所有必需通道有效、新鲜、AFE 故障可清除后，允许 CLEAR 返回待机。恢复区间与触发区间之间设置回差。
- 保护/状态机模块统一拥有负载使能权。CAN、日志和其他任务通过消息请求，不直接改写使能 GPIO。
- 复位后不自动恢复运行。第一版故障历史默认保留于本次运行日志；跨掉电故障历史存储未纳入范围。

#### 采样和时间规则

- 模拟输入阶段，暂定 100 ms 生成一组测量数据；五路 ADC 输入使用 3.3 V 范围内的分压信号，不将 5 V 或串联电池抽头直接接入 ADC。
- 后续 BQ76920 单体电压和电流更新约 250 ms，温度通道约 2 s。I²C 轮询更快不代表数据更新更快。[TI 数据手册](https://www.ti.com/lit/ds/symlink/bq76920.pdf)
- 温度优先用 STM32 ADC＋外接 10 kΩ NTC，保留原有 ADC 学习与验证路径。NTC 的 B 值、温度范围和分压阻值应按所购型号确认。
- 电压/电流及 MCU NTC 的更新超时可暂定为 1 s；如果改用 BQ 温度通道，温度超时单独暂定为 5 s。最终值依据实测刷新间隔调整。
- 数据有效标志和新鲜度按通道管理。周期上报可以重复最新值，但不能把重复上报时间写成新采样时间；输入值不变本身不代表采样失效。
- 保护响应时间分开记录：采样等待＋转换/滤波/去抖＋任务调度＋开关执行。软件确认故障到输出关闭的时间，不等于从物理故障发生到断开的总时间。
- 软件过流用于学习原型的限流条件演示，不能用慢速测量代替短路硬件保护；过流测试采用调低演示阈值或改变受限负载的方式。

#### FreeRTOS 初始划分

| 任务/模块 | 职责 | 通信设计意图 |
| --- | --- | --- |
| Acquisition | 读取 ADC 或 AFE，换算并维护各通道更新时间 | 向控制模块交付完整测量快照；可使用长度 1 的最新值队列 |
| Control | 保护判断、故障锁定、状态转换、负载输出 | 唯一输出所有者；接收命令队列，检查数据有效性和超时 |
| CAN | 接收并校验命令，上报快照/状态/故障 | 命令交给 Control；发送拥塞时不能阻塞保护任务 |
| Log | 输出串口日志，记录时间、事件和结果 | 日志队列限长；满时记录丢弃计数，不让日志拖慢控制 |
| Supervision | 检查关键任务运行情况，条件满足才喂狗 | 任务活性与测量新鲜度分别检查，避免每个任务各自无条件喂狗 |

### 核心板与调试器选购

STM32F103ZE 具有 72 MHz Cortex-M3、512 KB Flash、64 KB SRAM、ADC、DMA、I²C、UART 和 CAN，资源适合本项目；其应用供电范围为 2.0～3.6 V，本项目按 3.3 V 逻辑连接。[ST 产品资料](https://www.st.com/en/microcontrollers-microprocessors/stm32f103ze.html)

购买前检查：

1. 实物主芯片完整型号为 STM32F103ZET6，所附原理图与所售 PCB 版本一致；不要仅凭商品标题认定芯片与引脚相同。
2. 具备稳压、去耦、BOOT0、复位、明确的供电入口和 SWD 接口；调试连接需能使用 SWDIO、SWCLK、GND，并尽量引出 NRST。
3. 确认 ADC 输入、I²C、CAN 和 UART 可同时使用，没有被板载外设不可解除地占用；具体管脚表在拿到原理图后制定。
4. 核对外部晶振频率和供电方式，后续 CAN 位时序要与实际时钟一致。
5. 多排针核心板不一定适合直接插入面包板，允许板放桌面用杜邦线接信号。关注排针间距、丝印可读性及已焊接选项。
6. USB 接口可能只是供电或 MCU USB，不能默认它自带 USB 串口。厂商的 F103ZET6 核心板资料可作为文档完整性参考，不能用另一款板的接线图替代实物原理图。[野火核心板说明](https://doc.embedfire.com/stm32_products/must_read/zh/latest/doc/introduction_of_stm32/STM32/ebf_stm32f103zet6_core/stm32f103zet6_core.html)
7. 调试器需能在选用工具链中连接、擦写、命中断点及查看变量。问清驱动、线序、售后及是否为兼容产品；兼容版预算不等于原装价格。
8. 供电从一个明确入口提供。调试器的目标电压参考引脚不一定是供电输出；USB、ST-LINK、电源模块并接前必须核对，避免反向供电。

工具路线为 CubeMX＋HAL＋Keil，VS Code 编辑。当前已完成 HSE/PLL 与周期 ADC/UART 基础验证，具体版本与证据见开发记录。

### CAN 选购与接线边界

数据路径：

```text
STM32 内置 CAN 控制器的 TX/RX
          ↕
外接 CAN 收发器
          ↕ CANH / CANL
USB-CAN（带 CAN 接口）
          ↕ USB
电脑调试软件
```

- 推荐 3.3 V SN65HVD230 类收发器模块。SN65HVD230 是物理层收发器，支持最高 1 Mbit/s；选购模块仍需检查实际芯片、模式引脚和原理图。[TI 产品资料](https://www.ti.com/product/SN65HVD230)
- MCP2515 是独立 CAN 控制器，本项目使用 STM32 的 CAN 控制器，因此不把 MCP2515 SPI 模块作为首选收发器方案。[Microchip 产品资料](https://www.microchip.com/en-us/product/mcp2515)
- USB-CAN 必须支持正常模式主动发送、接收及 ACK，只有监听功能的设备无法完成双节点正常通信验证。核对 Windows 驱动、发送工具、协议文档及所需 API。
- 终端电阻只在总线两端配置，各 120 Ω；先确认模块及 USB-CAN 是否已经内置，避免重复并联。两只终端都接入时，断电测 CANH 与 CANL 间预期约 60 Ω。
- 初期使用短双绞线。非隔离双节点按同一低压台架的参考地设计；若选择隔离设备，按其手册连接总线侧参考地。
- 不因为模块标题写着“车载 CAN”就认定其电平、隔离或终端配置符合本项目。

### 电源、负载与模拟电芯

- 初期 MCU 可从板卡规定的 USB 入口供电；负载由独立可调限流直流电源供电，串联合适保险丝，负载电流不经过 MCU 排针、面包板或细杜邦线。
- 开关模块必须在 3.3 V 输入下可靠导通/关闭，输入悬空、MCU 复位时默认关闭。查看驱动级或 MOS 在实际栅压下的导通指标，不能只根据阈值电压判断。若控制输入并非直接驱动 MOS 栅极，应按模块接口电路检查。
- 第一版只切断放电负载，不做充电控制；单个 MOS 的单向开关不能被描述成完整双向电池隔离。
- 优先电阻性负载，功率按实际电压/电流计算并留降额余量，验证温升。暂不使用电机等感性负载。
- BQ 接入前优先采用厂家说明支持的电芯模拟方法。电阻分压式模拟器仅用于合适条件下的采样验证，均衡关闭；不能从其抽头供电或带负载，也不能把改变总电压误当作单独调节某一节电芯。
- 需要独立单节故障注入时，使用审查过的独立可调模拟方案或受控数据注入。普通共地电源的通道不能未经确认就串联。
- 此阶段不购买真实锂电池、不进行充电实验。后续若引入真实电芯，另做接线、参数和测试条件评审，并单独标记其验证范围。
