# 最小工程：逐项配置解释

日期：2026-10-15。按当前 bms_bringup 的实际 .ioc、.uvprojx、源码和构建日志解释。本轮只补充原理说明，不修改固件，不要求重复已通过的配置。

用户要求：此前每个配置步骤都需要解释。后续指导在每一步说明“做什么、为什么这样选、影响什么、如何验证”，再推进下一个可验证目标。提供操作路径不能替代原理说明。

## 1. 安装 STM32CubeF1 1.8.7

CubeMX 根据图形配置生成初始化代码，STM32CubeF1 提供这些代码依赖的 F1 系列 HAL、CMSIS 和示例等源码。HAL 是 ST 提供的硬件抽象层，例如 HAL_GPIO_Init 将引脚配置转换为寄存器操作；CMSIS 提供 Cortex-M 内核与器件相关的基础定义。

安装库是让电脑上的 CubeMX 能取得代码，并没有把固件写入 MCU。用户已确认 1.8.7 安装成功，本机也检查到对应包目录和必要文件。

若通过 Help → Manage embedded software packages → From Local 安装，应选择完整软件包 ZIP，工具负责检查和解包；具体实际安装途径尚未由用户补记。1.8.7 的 package.xml 声明基础版本为 1.8.0、补丁为 1.8.7，当前安装目录已有必要基础文件，不需重新下载或降级。

CubeMX 6.18.0、CubeF1 1.8.7、Keil 5.24 和 Compiler 5.06 是不同组件的版本号，无需彼此相同。[ST CubeF1 说明](https://www.st.com/en/embedded-software/stm32cubef1.html)

## 2. 在 MCU Selector 中选择 STM32F103ZETx

操作：搜索 STM32F103ZE，选择对应器件，核对 LQFP144、512 KiB Flash 和 64 KiB RAM，再点击 Start Project。

芯片型号决定可配置的引脚、外设、寄存器与存储器容量。当前 .ioc 的具体订货型号为 STM32F103ZET6，通用器件显示名为 STM32F103ZETx；x 表示此处按通用型号归类。其他容量的 F103 不能仅因属于同一系列就替代。

Flash 用于存放掉电后仍保留的程序和常量等；RAM 用于程序运行中的变量、栈、堆等。LQFP144 表示相应封装具有 144 个引脚，选它是为了匹配已订购的 MCU。

使用 MCU Selector，是按芯片创建工程。第三方核心板的实际板载 LED、晶振和接口仍要看板卡原理图，芯片型号本身不能告诉 CubeMX 这些板级连接。[ST 器件资料](https://www.st.com/en/microcontrollers-microprocessors/stm32f103ze.html)

验证：.ioc 的 Mcu.CPN=STM32F103ZET6、Mcu.Package=LQFP144；Keil 目标为 STM32F103ZE，Flash/RAM 地址范围匹配。

## 3. SYS → Debug → Serial Wire

选择 Serial Wire，使芯片保留 SWD 下载调试接口。ST-LINK 后续通过该接口访问 MCU，支持下载程序、暂停执行、断点和查看变量。

SWD 的两个主要信号是 PA13/SWDIO（调试数据）和 PA14/SWCLK（调试时钟）。真实接线还需确认地参考和供电/电压参考；本步骤只是保留接口，尚未接线。

选择它的原因是当前使用独立 ST-LINK，SWD 能满足下载调试需求，且只占用两个主要调试信号引脚。当前 HAL_MspInit 中生成 __HAL_AFIO_REMAP_SWJ_NOJTAG()，关闭 JTAG 并保留 SWD。

验证：.ioc 中 PA13、PA14 的 Mode 为 Serial_Wire；源文件 Core/Src/stm32f1xx_hal_msp.c 有上述 SWD 保留设置。

## 4. 保持内部 HSI 时钟

CPU 和外设计时依赖时钟。HSI 是芯片内部的 RC 振荡器，F103 的标称频率为 8 MHz；HSE 通常来自板上的外部晶体或时钟输入；PLL 是可用于倍频的锁相环。

当前保持 HSI，并未启用 PLL。原因是先完成最小工程，板上外部晶振型号和频率还未核对，使用内部时钟可以减少首次启动对板级信息的依赖。F103ZE 的最高工作频率为 72 MHz，这个能力不会使程序自动运行在 72 MHz。

当前代码的含义：

```c
RCC_OscInitStruct.PLL.PLLState = RCC_PLL_NONE;          // 本配置不使用 PLL
RCC_ClkInitStruct.SYSCLKSource = RCC_SYSCLKSOURCE_HSI;  // 系统时钟源为 HSI
RCC_ClkInitStruct.AHBCLKDivider = RCC_SYSCLK_DIV1;      // AHB 不分频
RCC_ClkInitStruct.APB1CLKDivider = RCC_HCLK_DIV1;        // APB1 不分频
RCC_ClkInitStruct.APB2CLKDivider = RCC_HCLK_DIV1;        // APB2 不分频
```

因此当前标称 SYSCLK、HCLK、PCLK1、PCLK2 均为 8 MHz。AHB、APB 是内部总线，对应不同内核/外设模块的时钟分配。后续定时器、UART、ADC、CAN 的时序参数都要基于实际时钟计算；CAN 阶段再结合速率和时钟精度确认方案。

验证：查看 main.c 的 SystemClock_Config 与 CubeMX 的 Clock Configuration，确认 HSI 为系统时钟源、总线频率为 8 MHz。尚未实测振荡器频率。

## 6. 点击 Generate Code

CubeMX 把选定的芯片、时钟、调试与外设配置转换为初始化源码，并生成 Keil 工程文件。它完成的是代码与工程生成，之后才由编译工具处理。

| 产物 | 用途 |
| --- | --- |
| bms_bringup.ioc | 保存 CubeMX 配置，以后可以重新打开修改并生成代码 |
| Core/Src/main.c | 程序入口、当前时钟与 GPIO 初始化、主循环 |
| Drivers | HAL、CMSIS 等依赖源码和头文件 |
| MDK-ARM/startup_stm32f103xe.s | 启动汇编、向量表、栈/堆预留及进入 C 程序的入口流程 |
| MDK-ARM/bms_bringup.uvprojx | Keil 工程，包含目标芯片、源文件、编译和链接设置 |

用 Open Project 或双击 .uvprojx 进入 Keil。保留 .ioc 便于追踪图形配置；保留源码和工程便于阅读与构建。

当前生成代码反映配置很少：main 依次执行 HAL_Init、SystemClock_Config、MX_GPIO_Init，最后进入空主循环；MX_GPIO_Init 只开启 GPIOA 时钟，没有 LED 或负载输出的初始化。

## 7. Keil → Options for Target → Target 中的编译器

实际选择 Arm Compiler 5.06 update 5 (build 528)。C 编译器把 C 源码转为 ARM 机器指令相关的目标文件，汇编器处理启动汇编，链接器再组合它们并安排地址。

本轮先使用已经安装、能够完成当前工程构建的 Compiler 5，建立可复现的基础工程。电脑也安装了 Compiler 6.7，但未用于此次构建。以后更换编译器需要单独记录并验证。

验证：.uvprojx 中 pArmCC 指向 5060528，uAC6=0；构建日志显示 Using Compiler V5.06 update 5 (build 528)。实际构建日志是确认所用编译器的直接证据。

## 8. 核对 Device、DFP 和存储器

Device 选择 STM32F103ZE，使 Keil 按目标芯片配置工程。Keil 的 STM32F1xx_DFP 2.2.0 提供器件描述和调试/Flash 编程等支持；CubeF1 提供 HAL 等源码，两者职责不同。

当前工程的 Flash 起始地址 0x08000000、大小 0x80000（512 KiB）；RAM 起始地址 0x20000000、大小 0x10000（64 KiB）。这些地址/容量让链接器知道程序与数据可以放在哪里，也决定其检测区域超限的依据。

验证：.uvprojx 的 Device、PackID 和 Cpu 地址范围；后续 MAP 可以查看每个段实际放置的地址。当前构建通过，下载算法和 ST-LINK 连接仍待实物验证。

## 9. Output → Create HEX File

当前工程勾选此项，链接完成后由 fromelf 额外生成 HEX。

AXF 是包含固件映像及符号/调试信息等内容的 ELF 格式文件，Keil 可以据此做源码调试。Intel HEX 是按记录保存地址、数据和校验等信息的文本格式，适合支持该格式的独立烧录工具。

生成 HEX 便于后续烧录使用；Keil 调试并不要求必须额外生成 HEX。勾选此项不会把程序写进 MCU。

验证：.uvprojx 的 CreateHexFile=1；构建日志出现 FromELF: creating hex file，输出目录有 .hex。[Keil HEX 输出说明](https://www.keil.com/support/man/docs/uv4cl/uv4cl_ca_createhexfile.htm)

## 10. 按 F7 / Build

Build 对需要更新的源文件执行编译/汇编，再链接必要目标文件和库；当前链接得到 AXF，随后生成 HEX。Rebuild 用于重新构建全部内容，常规小改动先用 Build。

编译阶段主要检查单个源文件的语法、类型和声明等；链接阶段组合实现，解析跨文件引用，安排代码与数据的位置。构建成功证明这套配置和源码能够产出固件映像。

本次结果为 0 Error(s)、0 Warning(s)，属于最小工程编译验收通过。开发板运行、实际时钟精度、外设接线和保护行为需要上板测试。

大小记录：Code=2096、RO-data=372、RW-data=16、ZI-data=1632；MAP 的 ROM 总量为 2484 B，RAM 分配为 1648 B。

## 11. 当前保留的默认项与代码保护区域

这些不是本轮新要求修改的设置，用来帮助理解生成结果：

- HAL 时基为 SysTick，默认每 1 ms 更新软件计数，支持 HAL_GetTick 和 HAL_Delay。它不表示所有外设都按 1 ms 采样，也不表示已经启用 FreeRTOS。
- 当前启动文件预留栈 0x400=1024 B、堆 0x200=512 B。栈用于函数调用、局部变量和异常现场等；这块堆为 C 运行库的动态内存区域。后续 FreeRTOS 的任务栈与堆管理需要另行选择和验证。
- .ioc 的 KeepUserCode=true。修改自动生成文件时，自写内容放在匹配的 USER CODE BEGIN/END 区域；后续业务逻辑尽量放独立文件。重新生成会更新生成区域，不能假定所有手写修改都会保留。
