## 已实现的内容

当前实现位于 [bms_protection.h](../MCU/projects/bms_bringup/Core/Inc/bms_protection.h) 和 [bms_protection.c](../MCU/projects/bms_bringup/Core/Src/bms_protection.c)，依赖 [bms_types.h](../MCU/projects/bms_bringup/Core/Inc/bms_types.h)。

| 函数 | 检查内容 | 返回结果 |
| --- | --- | --- |
| Bms_CheckCellOverVoltage | 单路电压的基本有效性与过压阈值 | 数据无效、未触发过压、触发过压 |
| Bms_CheckSampleFreshness | 单路测量的标志、来源及更新时间 | 数据或参数无效、未超时、超时 |

过压检查中，空指针、valid 不为 1、来源为 NONE、负电压、非正阈值均返回无效；有效电压达到阈值就触发过压。

时效检查中，空指针、valid 不为 1、来源为 NONE、max_age_ms 为 0 均返回无效。数据年龄通过无符号减法计算，达到允许的最大年龄就判超时。单独通过时效检查不代表数值正常，单独未触发过压也不代表数据没有过期。

当前来源检查只排除 NONE；采样驱动尚未实现，valid 标志由测试构造。后续驱动的实际有效性检查需另行验证。

## 时间戳的约定

- timestamp_ms 记录取得新采样时的毫秒计数。
- now_ms 与 timestamp_ms 必须来自同一个计数器；未来可统一使用 HAL_GetTick()。
- 采样先于检查，实际间隔小于一个完整的 32 位毫秒计数周期，约 49.7 天。
- 计数回绕后仍通过无符号减法计算年龄，不能简单用当前计数是否更大判断。
- timestamp_ms 为 0 可以表示启动时刻；是否有采样依靠有效标志和来源判断。
- 重复打印或 CAN 上报旧值时，不刷新采样时间戳。

4200 mV、500 ms 都是软件测试参数，尚未冻结实物电池的保护阈值或各通道超时值。

## 如何重新验证

在项目根目录的 PowerShell 中逐行执行。每次编译成功后再运行对应程序；编译失败时不能用旧程序的通过结果作为本次证据。

```powershell
Set-Location -LiteralPath 'D:\嵌入式学习\电池管理系统'
New-Item -ItemType Directory -Force -Path '.\build\host' | Out-Null

gcc -std=c99 -Wall -Wextra -Werror -I MCU/projects/bms_bringup/Core/Inc MCU/projects/bms_bringup/Core/Src/bms_protection.c MCU/projects/bms_bringup/Core/tests/test_bms_ov.c -o build/host/test_bms_ov.exe
.\build\host\test_bms_ov.exe

gcc -std=c99 -Wall -Wextra -Werror -I MCU/projects/bms_bringup/Core/Inc MCU/projects/bms_bringup/Core/Src/bms_protection.c MCU/projects/bms_bringup/Core/tests/test_bms_timeout.c -o build/host/test_bms_timeout.exe
.\build\host\test_bms_timeout.exe
```

- GCC 生成 Windows 程序，运行真正的保护函数；这里没有模拟 ADC、电气特性或 FreeRTOS 调度。
- -I 指定头文件目录；-o 指定输出文件；-std=c99 选择 C99。
- -Wall、-Wextra 开启警告；-Werror 将警告视作构建失败。
- assert 比较实际与预期结果；命令没有定义 NDEBUG，因此断言有效。
- 每个测试文件都有自己的 main()，应分别构建，不加入 Keil MCU 目标。
