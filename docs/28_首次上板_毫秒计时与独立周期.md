# 首次上板：毫秒计时与独立周期

日期：2026-10-17。前置：用户确认USART1发送成功，串口基线为cee6da8。本步是待用户实施的教程，尚未修改代码或验收。

## 本步目标与边界

只修改main.c的用户区，取消两次HAL_Delay(500u)，让D3每500 ms翻转、USART1每200 ms发送一次。两个动作各用一份时间记录；只改变串口周期不会同时改变LED周期。本步不修改CubeMX、接线、时钟、串口参数或中断。

这为后续主循环加入采样和保护留出执行机会。HAL_UART_Transmit仍为轮询发送，整个主循环没有变成完全不阻塞的系统；这也不是FreeRTOS任务调度。

## 原理与本地依据

本机CubeF1 1.8.7：

- Drivers/STM32F1xx_HAL_Driver/Src/stm32f1xx_hal.c：HAL_InitTick默认配置1 ms SysTick；HAL_IncTick增加uwTick；HAL_GetTick直接返回uwTick；HAL_Delay在while中反复读时间直到满足延时。
- Core/Src/stm32f1xx_it.c：SysTick_Handler调用HAL_IncTick。
- Drivers/STM32F1xx_HAL_Driver/Src/stm32f1xx_hal_uart.c：HAL_UART_Transmit等待TXE及TC标志，为阻塞发送。
- Core/Src/gpio.c：LED初始化为高电平，即D3熄灭；之后每次Toggle在亮与灭间切换。

HAL_Delay(500u)期间中断仍可运行，但主循环停在延时函数里。换成if判断后，到时间才执行动作，没到时间就继续向下运行，再进入下一轮。

每个周期的判断都是“当前计数减上次计数是否达到周期”。例如上次100 ms、现在600 ms，差值500 ms，需要翻转一次。

## 修改位置与完整代码

退出Keil调试，在VS Code打开Core/Src/main.c。保留HAL_Init、SystemClock_Config、MX_GPIO_Init、MX_USART1_UART_Init及原有include。所有新增内容放在对应USER CODE区内，避免再次生成时丢失。

PD区放周期常量：

```c
/* USER CODE BEGIN PD */

/* 单位都是毫秒；LED每翻转两次才完成一次亮灭。 */
#define LED_PERIOD_MS   500u
#define UART_PERIOD_MS  200u

/* USER CODE END PD */
```

PV区保留消息并增加两个时间记录，替换此区即可，不要重复定义uart_message：

```c
/* USER CODE BEGIN PV */

/* 保留原来的固定消息，末尾的回车换行用于电脑显示。 */
static const uint8_t uart_message[] = "BMS UART1 OK\r\n";

/* 分别记住上一次翻转LED、发送串口消息的时间。 */
static uint32_t led_last_ms = 0u;
static uint32_t uart_last_ms = 0u;

/* USER CODE END PV */
```

在两个外设初始化调用之后的USER CODE BEGIN 2区建立计时起点：

```c
/* USER CODE BEGIN 2 */

/* 外设初始化完成后，从此刻开始计算两个周期。 */
led_last_ms = HAL_GetTick();
uart_last_ms = led_last_ms;

/* USER CODE END 2 */
```

把原来的while用户区整体替换如下，移除旧的无条件发送和两次HAL_Delay：

```c
/* USER CODE BEGIN WHILE */
while (1)
{
  /* USER CODE END WHILE */

  /* USER CODE BEGIN 3 */

  /* 读取当前毫秒计数；读取时间不会等待。 */
  uint32_t now_ms = HAL_GetTick();

  /* 距离上次翻转已经过了500毫秒，才改变一次灯的状态。 */
  if ((uint32_t)(now_ms - led_last_ms) >= LED_PERIOD_MS)
  {
    /* 记下本次时间；未到下一周期时，主循环可以做其他事。 */
    led_last_ms = now_ms;
    HAL_GPIO_TogglePin(LED_STATUS_GPIO_Port, LED_STATUS_Pin);
  }

  /* 串口使用自己的计时，不必等LED完成一轮亮灭。 */
  if ((uint32_t)(now_ms - uart_last_ms) >= UART_PERIOD_MS)
  {
    uart_last_ms = now_ms;

    /* 发送仍然采用轮询方式；100u是超时上限，不是固定等待时间。 */
    if (HAL_UART_Transmit(&huart1,
                          uart_message,
                          (uint16_t)(sizeof(uart_message) - 1u),
                          100u) != HAL_OK)
    {
      /* 本次基础实验发送失败时停在错误处理，方便调试定位。 */
      Error_Handler();
    }
  }
}
/* USER CODE END 3 */
```

main.c使用的头文件已经提供uint32_t与HAL函数声明，不需要额外添加头文件。当前Keil工程已启用C99，允许在循环块中声明now_ms。

## 逐项理解

| 写法 | 含义 |
| --- | --- |
| LED_PERIOD_MS | 每次翻转间隔500 ms，完整亮灭周期约1000 ms |
| UART_PERIOD_MS | 发送间隔200 ms，约每秒5条，本步用于直观看到独立周期 |
| led_last_ms / uart_last_ms | 两个动作各自的上一次执行时间，不能共用一个last变量 |
| now_ms | 本轮统一读取的时间快照 |
| >= | 即便循环没有恰好碰上周期边界，超过周期也能执行 |
| 两个独立if | 同一轮两个动作都到时间时，都可以执行；不能改成else if而使其中一个依赖另一个 |
| HAL_GPIO_TogglePin | 翻转GPIO输出；D3低有效，每翻转一次改变亮灭状态 |
| last_ms = now_ms | 从本次检查时间重新计时，错过多个周期也只执行一次，不集中补发 |

这里使用从本次实际检查时刻重新计时的简单策略，存在主循环耗时引起的小幅延后和累计漂移，不称为精确周期调度。首次串口消息在初始化后约200 ms，首次D3翻转约500 ms；此前固定消息在进入循环时立即发送，启动时序不同是预期行为。

### 为什么使用无符号相减

HAL_GetTick为uint32_t毫秒计数，约49.7天回绕。以当前0x00000020、上次0xFFFFFFF0为例，无符号差值为0x30，即48 ms，仍能算出跨回绕的间隔。短周期且持续检查时可使用这种写法；不能在不检查的情况下跨过完整计数周期后还指望恢复真实经过时间。

避免直接写now_ms >= last_ms + period_ms，因为截止时间加法回绕后可能误判。强制转换用于明确按uint32_t差值处理。

### 串口发送仍会占用主循环

消息14字节，115200/8N1每字节需要起始位、8数据位、停止位，共10位。理论线传输时间为14×10/115200秒，约1.22 ms，实际还受代码和时钟影响。100u为超时上限，不表示每次发送固定等100 ms。异常返回时仍进入现有Error_Handler，作为本次调试策略。

主循环现在可以在两次到期之间执行其他工作，但不能据此宣称采样保护时限已经满足。CPU仍反复执行while，没有休眠；后续接入真实控制时再核对每项耗时，并按需要采用中断/DMA或FreeRTOS。
