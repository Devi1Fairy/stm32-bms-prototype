## 本步目标

新增 Bms_CheckCellUnderVoltage()，返回数据无效、未触发欠压、已触发欠压三种结果，并用电脑端测试验证边界与无效输入。

本步只增加单节检查，不修改现有 Bms_CheckPackVoltages() 的接口或结果结构体。下一步再将欠压接入三节汇总，增加对应位图，并验证上下限参数关系。

3000 mV 仅用于测试，不是对实物电池保护阈值的建议。实际阈值需结合最终电池类型和规格确定。

| 有效数据的电压 | 结果 |
| --- | --- |
| 3001 mV | 未触发 |
| 3000 mV | 触发 |
| 2900 mV | 触发 |
| 0 mV | 触发 |

负电压在当前数据约定下无效。value 为 0 不等于“尚未采集”；如果 valid=0 或来源为 NONE，则返回无效。采样驱动以后负责实际的有效性标记，本测试中的标记和来源均由软件构造。

## 第一步：添加类型和声明

打开 [bms_protection.h](../MCU/projects/bms_bringup/Core/Inc/bms_protection.h)，在最后的 #endif 前面添加，保留已有内容：

```c
/* 单节电池的欠压检查结果，不代表整组电池的完整状态。 */
typedef enum
{
    BMS_UV_DATA_INVALID = 0, /* 数据或阈值无效，当前无法判断 */
    BMS_UV_NOT_TRIGGERED,   /* 没有触发本项欠压 */
    BMS_UV_TRIGGERED        /* 已触发欠压 */
} BmsUvResult;

/*
 * 检查一节电池是否欠压。
 * cell：待检查的单体测量数据，只读取，不修改。
 * threshold_mv：欠压阈值，单位 mV，必须大于 0。
 * 本函数检查数值和基本有效性；采样超时仍由时效函数检查。
 */
BmsUvResult Bms_CheckCellUnderVoltage(
    const BmsMeasurement *cell,
    int32_t threshold_mv);
```

## 第二步：添加函数实现

打开 [bms_protection.c](../MCU/projects/bms_bringup/Core/Src/bms_protection.c)，在已有函数后面添加。文件顶部已经包含提供 NULL 的 stddef.h。

```c
BmsUvResult Bms_CheckCellUnderVoltage(
    const BmsMeasurement *cell,
    int32_t threshold_mv)
{
    /*
     * 先检查指针，再访问对象成员。
     * valid 不为 1 或没有来源的数据，不能用于正常电压判断。
     */
    if (cell == NULL ||
        cell->valid != 1u ||
        cell->source == BMS_SOURCE_NONE)
    {
        return BMS_UV_DATA_INVALID;
    }

    /* 负电压和非正数阈值不符合本函数的输入约定。 */
    if (cell->value < 0 || threshold_mv <= 0)
    {
        return BMS_UV_DATA_INVALID;
    }

    /*
     * 本项目约定：达到或低于欠压阈值，就触发欠压。
     * value 为 0 且标志有效时，也应触发，不能写成 value <= 0 判无效。
     */
    if (cell->value <= threshold_mv)
    {
        return BMS_UV_TRIGGERED;
    }

    return BMS_UV_NOT_TRIGGERED;
}
```

过压使用 value >= threshold_mv，欠压使用 value <= threshold_mv。当前两种检查都约定包含相等的边界。

本函数只检查基本标志、来源、数值与阈值，不判断时间戳；组合使用时仍需先检查数据是否过期。暂不增加滞回、持续时间判定或故障锁存，这些属于后续组合保护与状态机的实现。

## 第三步：编写测试

新建 MCU/projects/bms_bringup/Core/tests/test_bms_uv.c：

```c
#include <assert.h>
#include <stdio.h>
#include "bms_protection.h"

int main(void)
{
    BmsMeasurement cell = {0};

    /* 3000 mV 仅用于软件测试，实物电池的保护阈值尚未确定。 */
    const int32_t threshold_mv = 3000;

    cell.valid = 1u;
    cell.source = BMS_SOURCE_SIMULATED;

    /* 1：正常电压，不触发欠压。 */
    cell.value = 3700;
    assert(Bms_CheckCellUnderVoltage(&cell, threshold_mv)
           == BMS_UV_NOT_TRIGGERED);

    /* 2：高于阈值 1 mV，不触发。 */
    cell.value = 3001;
    assert(Bms_CheckCellUnderVoltage(&cell, threshold_mv)
           == BMS_UV_NOT_TRIGGERED);

    /* 3：刚好达到阈值，触发欠压。 */
    cell.value = 3000;
    assert(Bms_CheckCellUnderVoltage(&cell, threshold_mv)
           == BMS_UV_TRIGGERED);

    /* 4：低于阈值，也触发欠压。 */
    cell.value = 2900;
    assert(Bms_CheckCellUnderVoltage(&cell, threshold_mv)
           == BMS_UV_TRIGGERED);

    /* 5：标志有效的零电压，应触发欠压。 */
    cell.value = 0;
    assert(Bms_CheckCellUnderVoltage(&cell, threshold_mv)
           == BMS_UV_TRIGGERED);

    /* 6：同样是零电压，标志无效时应返回数据无效。 */
    cell.valid = 0u;
    assert(Bms_CheckCellUnderVoltage(&cell, threshold_mv)
           == BMS_UV_DATA_INVALID);
    cell.valid = 1u;
    cell.value = 3700;

    /* 7：负电压不是本项目认可的有效单体电压。 */
    cell.value = -1;
    assert(Bms_CheckCellUnderVoltage(&cell, threshold_mv)
           == BMS_UV_DATA_INVALID);
    cell.value = 3700;

    /* 8：没有来源，不能当作有效测量。 */
    cell.source = BMS_SOURCE_NONE;
    assert(Bms_CheckCellUnderVoltage(&cell, threshold_mv)
           == BMS_UV_DATA_INVALID);
    cell.source = BMS_SOURCE_SIMULATED;

    /* 9：零阈值属于参数错误。 */
    assert(Bms_CheckCellUnderVoltage(&cell, 0)
           == BMS_UV_DATA_INVALID);

    /* 10：负阈值同样属于参数错误。 */
    assert(Bms_CheckCellUnderVoltage(&cell, -1)
           == BMS_UV_DATA_INVALID);

    /* 11：空指针应返回无效，不能访问它的成员。 */
    assert(Bms_CheckCellUnderVoltage(NULL, threshold_mv)
           == BMS_UV_DATA_INVALID);

    puts("11 undervoltage tests passed.");
    return 0;
}
```

“有效零值触发”和“无效零值返回无效”两项用于说明：测量值和数据质量是两个独立信息。

该测试文件有自己的 main()，只用于电脑程序，不加入 Keil MCU 编译目标。
