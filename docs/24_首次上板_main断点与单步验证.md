# 首次上板：main断点与单步验证

日期：2026-10-17。用户已反馈编译下载完成。本步唯一目标：在实物芯片上暂停并单步执行main()初始化流程，再复位重新到达同一位置。用户已确认各步骤通过，并提供寄存器窗口截图；下文保留教程，末尾补充实际验收记录。

## 为什么下载后还要做这一步

编译把源代码转换为机器码，下载把固件写入芯片Flash，断点与单步则让我们观察CPU执行到哪里。写入完成与实际执行是不同的验收项。

STM32复位后先执行启动代码，完成运行环境初始化，再进入main()。断点让CPU执行到指定位置时暂停，Keil通过ST-LINK查看当前指令及寄存器等状态。它不会直接修改项目C代码。

本次使用现有代码，不新增LED或BMS调用，避免同时引入新的验证对象。

## 当前代码位置

打开项目中的Core/Src/main.c，不是电脑测试目录中带独立main()的测试文件。

本次只读核对的行号：

| 行号 | 可执行语句 | 作用 |
| --- | --- | --- |
| 74 | HAL_Init(); | 初始化HAL基础环境和系统时基等 |
| 81 | SystemClock_Config(); | 配置本工程时钟，当前使用内部HSI 8 MHz |
| 88 | MX_GPIO_Init(); | 执行当前GPIO初始化；现有代码仅开启GPIOA时钟 |
| 95附近 | while (1) | 当前为空循环，没有LED控制或BMS控制调用 |

后续修改可能改变行号，以语句内容为准。第一次断点放在HAL_Init();这一行，不放在注释、空行或大括号上；空循环也可能缺少对应的独立源码调试位置。

## 第一步：设置断点

在Keil编辑器打开main.c，将光标放到HAL_Init();行，按F9。应出现断点标记，通常为红色圆点；也可以双击该行左侧的断点边栏。

断点标记表示希望执行到这里暂停，是否命中还需进入实物调试确认。只在VS Code文本窗口点断点，不会自动成为本次Keil会话中的断点。

## 第二步：进入实物调试

保持开发板供电与SWD连接，在Keil按Ctrl+F5，或选择Debug → Start/Stop Debug Session。

本机现有设置选择ST-LINK目标驱动，Run to main与进入调试前更新Flash已启用，因此：

- 进入会话可能自动再次下载固件，这是已有配置的行为。
- 正常情况下会暂停在main()入口附近，通常可看到HAL_Init();附近的黄色执行箭头。
- 如果已经停在HAL_Init();，直接进行下一步，不要为了“命中”再按F5让它跑进空循环。

黄色箭头表示下一条待执行的源码语句。箭头停在HAL_Init();时，该次调用通常还没有执行完成。

如果会话已经在运行，先通过Debug → Stop暂停，再使用Debug → Reset CPU；若复位后仍未停到HAL_Init();，按F5运行到该断点。若出现连接、复位或下载错误，先保留原文，不修改电源接线或猜测故障根因。

RST若仍留空，Connect应与前一步三线方案匹配为Normal。实际修改情况尚未从用户截图确认。

## 第三步：单步执行初始化

CPU暂停在HAL_Init();时：

1. 按一次F10，正常应执行完HAL_Init()并停到SystemClock_Config();附近。
2. 再按一次F10，正常应执行完时钟配置，停到MX_GPIO_Init();附近。

F10是Step Over：会执行函数调用并等待返回，然后暂停在后续语句，不逐行展示函数内部。F11为进入函数内部，本步不需要使用。

源码行的对应位置可能受编译器调试映射影响，允许停在相邻的可执行位置；关键是初始化调用能够返回，执行位置按预期推进。不要仅凭文本光标移动判断单步成功，应观察调试执行箭头。

本步不要求在空while循环上设断点，也不需要执行到BMS控制器：目前main()没有调用它。

## 第四步：复位后再次到达

保留HAL_Init();的断点，在调试会话中选择Debug → Reset CPU。

- 如果复位后已经停在HAL_Init();附近，说明再次到达目标位置。
- 如果停在启动代码，按F5运行，应在HAL_Init();断点处暂停。
- 如果持续运行不暂停或出现错误，保留当前窗口和输出，反馈后再排查。

这一步验证复位后能够重新进入固件入口，当前仍在调试器参与的条件下，不等于已经验收断开调试器后的独立启动。

完成观察后，可以按Ctrl+F5退出调试会话回到编辑状态。

## 常用按键的区别

| 按键或菜单 | 本步用途 |
| --- | --- |
| F9 | 设置或移除当前行断点 |
| Ctrl+F5 | 进入或退出调试会话 |
| F10 | 执行当前语句，跨过函数内部 |
| F5 | 持续运行，直到断点或手动暂停 |
| Debug → Reset CPU | 让目标CPU重新开始复位流程 |
| Debug → Stop | 暂停正在运行的CPU |

快捷键与操作意义参见[Keil官方快捷键表](https://www.keil.com/support/man/docs/uv4/uv4_dg_shortkeys.asp)和[Keil调试菜单说明](https://www.keil.com/support/man/docs/uv4cl/uv4cl_ui_debug.htm)。
